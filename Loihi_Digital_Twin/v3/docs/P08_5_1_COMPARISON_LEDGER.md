# P08.5.1 — NxTF Comparison Ledger and Comparability Freeze

## Purpose

P08.5 is the final comparison/closure stage. Before writing a thesis-facing comparison, P08.5.1 freezes a machine-readable ledger that answers two separate questions for every metric:

1. **Where did each value come from?**
2. **What kind of comparison, if any, is defensible?**

This prevents quantities that happen to be numeric from being treated as equivalent measurements when their architecture, compiler, representation, or physical measurement boundary differs.

The ledger is generated by:

```text
applications/mnist_v2_nxtf/mnist_v2_nxtf/comparison_ledger.py
```

and the verification gate is:

```text
Loihi_Digital_Twin/v2/scripts/run_p08_5_1_comparison_ledger.sh
```

## Comparison classes

Every row must use exactly one comparison class.

### `DIRECTLY_COMPARABLE`

The quantity has a sufficiently aligned semantic and unit boundary to place the two values side by side without an architecture-specific warning beyond normal experiment context. Current examples are the MNIST task/classes and the 100-algorithmic-timestep primary horizon.

### `COMPARABLE_WITH_RECONSTRUCTION_CAVEAT`

The quantity itself has the same semantic meaning, but the exact NxTF benchmark topology/checkpoint or implementation is not available. Accuracy/error, neuron count, parameter count, and expanded connection count are in this category. Side-by-side comparison is useful, but it must not be presented as an exact reproduction result.

### `CONTEXT_ONLY`

Both sides have numeric values, but the underlying accounting or compiler model is materially different. P08.5.1 places the following here:

- NxTF `6,746` shared weights versus P06 `64,235` stored shared parameters/templates;
- NxTF `14` Loihi neurocores versus P06 `5` project logical cores.

These values must not be ratioed into claims such as "X times more efficient" because the representations/partitioners are not equivalent.

### `PROJECT_SPECIFIC`

The metric describes FPGA-v2 implementation behavior for which the paper has no matching quantity: K26 resident contexts, physical engine count, paging activity, normalized packet traffic, PL clock, dispatch cycles, URAM use, and representative physical-conformance scope.

### `NOT_COMPARABLE`

The NxTF paper reports a physical measurement, but P08 has no equivalent workload-specific K26 measurement boundary. Native-Loihi energy (`0.66 mJ/sample`) and latency (`6.65 ms/sample`) are frozen in this category.

They remain useful published context but cannot be compared numerically against the representative K26 deep-core dispatch.

## Source/fidelity labels

Comparison class is distinct from source fidelity. Each side of every row also carries a fidelity label such as:

```text
SOURCED_EXACT
SOURCED_APPROXIMATE
SOURCED_STYLE_OR_RANGE
PROJECT_MEASURED
PROJECT_RECONSTRUCTION
DERIVED_FROM_ACCEPTED_MEASUREMENT
NOT_AVAILABLE
```

For example, the paper's approximately `4k` neurons and approximately `7k` trainable parameters are `SOURCED_APPROXIMATE`, while the project's `4,218` neurons and `7,006` parameters are exact values of the accepted `PROJECT_RECONSTRUCTION`.

## Frozen quantitative anchors

The ledger currently contains 24 rows. Important cross-system anchors are:

| Metric | NxTF | FPGA-v2 P08 | Boundary |
|---|---:|---:|---|
| Primary horizon | 100 timesteps | 100 timesteps | directly comparable |
| ANN test error | 0.74% | 1.26% | reconstruction caveat |
| SNN test error | 0.79% | 1.76% | reconstruction caveat |
| ANN→SNN error increase | 0.05 pp | 0.50 pp | reconstruction caveat |
| Neurons | ~4,000 | 4,218 | reconstruction caveat |
| Trainable parameters | ~7,000 | 7,006 | reconstruction caveat |
| Expanded/discrete connections | ~341,000 | 338,880 | reconstruction caveat |
| Shared/stored weights | 6,746 | 64,235 P06 stored entries | context only; different representation |
| Mapped cores | 14 Loihi neurocores | 5 P06 logical cores | context only; different compiler/resource model |
| Native energy | 0.66 mJ/sample | no equivalent measurement | not comparable |
| Native latency | 6.65 ms/sample | no equivalent measurement | not comparable |

Project-specific implementation observations remain separate, including:

```text
resident contexts: 3
physical engines: 1
representative forward page loads: 497

```

The `38.65 us` value is only `3865 / 100 MHz`; it is one logical-core dispatch, not per-sample inference latency.

## Overclaim guardrails

The validator requires all of these statements to remain false:

```text
native_loihi_energy_is_direct_fpga_comparison = false
native_loihi_latency_is_direct_fpga_comparison = false
shared_weight_counts_use_same_storage_model = false
mapped_core_counts_use_same_compiler_model = false
representative_dispatch_cycles_are_full_sample_latency = false
full_100_timestep_inference_physically_replayed_over_jtag = false
post_test_model_or_conversion_selection = false
```

The tests intentionally mutate an unsafe energy row and require ledger validation to reject it.

## Generated artifacts

A successful gate writes deterministic artifacts to:

```text
applications/mnist_v2_nxtf/artifacts/p08_5_1_comparison_ledger/
├── p08_5_comparison_ledger.json
└── p08_5_comparison_table.md
```

The JSON carries a deterministic SHA-256 ledger fingerprint. The Markdown table is rendered only from the validated ledger and shows a numeric delta only when `allow_numeric_delta=true`.

## Acceptance boundary

P08.5.1 can be accepted when:

- the regression tests pass;
- two independent ledger generations are byte-identical;
- the accepted P08 artifact identities match exactly;
- all 24 metric rows validate;
- the comparison-class counts remain frozen;
- the accuracy/structure anchors match the accepted source/project values; and
- all non-comparability/overclaim guardrails remain enforced.

P08.5.1 does not yet close P08. It freezes the evidence/comparability basis that P08.5.2 will use to produce the final thesis-facing comparison and quantitative interpretation.
