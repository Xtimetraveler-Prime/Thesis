### Interpret only what is proven

- The earlier accepted P03.2c physical width measurement showed `FPD afi_fs=0x00000A00` => **128-bit**, matched by accepted FPD128/SmartConnect design; see `docs/P03_2C_PS_HPM_WIDTH_BOOT_REMEDIATION.md`, `docs/P03_2C_ACCEPTANCE.md`.
- Current `0x00002560` is **64-bit**, a factual contradiction with the accepted FPD128 PS↔PL route *if that PL image is present*. The loaded PL bitstream image and its reset/clock/AXI aperture have **not** been established. The timeout alone does not prove whether the PL image is absent, the AXI interface width differs, the PL is held in reset, an isolation/clock is disabled, or the bus is otherwise unavailable.
- AMD UG1087 documents the FPD static width selector, 9:8 encoding 00=32, 01=64, 10=128; **do not modify during active operation**. AMD UG1085 Chapter 15 PS Interconnect, AXI Timeout Block recommends that after the first timeout the affected system be treated as needing restart. **Do not repeat `mrd 0xA4000000` in the same live session.**
- Never use `mwr` to change FPD width, load a new bitstream over currently running Linux, run the old `p03_2c_xsdb_ps_axi_width_diag.tcl` (it **halts A53**), `dow`, `rst`, `con`, or dispatch inference as troubleshooting. A normal controlled board reboot and boot/PL ownership inventory come first.

### Patch and tests (additive branch, no frozen edits)

- `vivado/p07_b4g_readonly_shell.tcl`: Immediately after reading `FPD_RAW`, decode selector and print `P07_B4G_FPD_HPM0_WIDTH_BITS`. If not 128, print `P07_B4G_PS_WIDTH_MISMATCH_FPD=1` and **fail before any 0xA4000000 PL read**. Always disconnect; failure path also prints `P07_B4G_A53_ELF_DOWNLOAD_AUTHORIZED=0`. The original fully read-only six-register full probe remains unchanged for correct FPD128.
- `vivado/p07_b4g_ps_width_only.tcl`: **separate optional after-reboot PS-only script** reading only static `FPD_SLCR.afi_fs` at `0xFD615000` and `LPD_SLCR.afi_fs` at `0xFF419000` through PSU/APU using `mrd -force -value -size w`. No PL memory reads, DDR access, XSDB CPU halt/reset, register writes or bitstream programming. Requires literal `READ_ONLY_OPERATOR_APPROVED` and local XSDB. Prints both raw and decoded fields; **never** declares P03 shell PASS or permits ELF download.
- `tests/test_p07_b4g_width_timeout_regression.py` adds simulated tclsh/fake XSDB tests: exact `0x2560` must generate **one** PS read and **zero** PS→PL reads; FPD128 still reaches six reads; PS-only script performs exactly two PS reads even if FPD64, reports errors and disconnects safely. `.github/workflows/p07_b4gh_native.yml` runs all B4g/h fake XSDB and transcript tests together. These tests are **not real board evidence**.
