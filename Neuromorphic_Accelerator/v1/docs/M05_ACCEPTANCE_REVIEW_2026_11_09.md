## Exact acceptance envelope and nonclaims

Admitted on-chip rolling kernel supports **at most 1024 neurons, 4096 synapses, 4096 signed-W16 deliveries per tick, 64 ticks per invocation and positive recurrent delays 1..8**. External input must be tick-sorted. The eight-slot wheel aggregates signed contributions exactly, tracks zero touches and deliveries and evaluates only eligible neuron states; it is not an event-by-event packet-preserving FIFO. One HLS invocation is a bounded session, not a continuous unbounded workload. Failure after provisional output requires discard/quarantine until final successful return; M05.11c simulated shell tests status and no partial publish on failure. This is an exact-scope prototype, not a published physical network-throughput or energy claim.

**Explicitly NOT M05 acceptance blockers; DEFER to M06 integration/experiments:** original PS DDR_LOW mapped aperture is not evidence of safe OS-owned DDR; the 256-bit DMA-to-128-bit PS HP0 SmartConnect functional conversion, 63 unwaived original BD warnings, AWUSER/ARUSER and internal packed high-bit semantics, DMA bursts/strobes/IDs/responses/backpressure when transferring to real memory, page identity/dirty eviction/restore, host PS Linux allocator and memory ownership, actual physical board programming/JTAG and whole-system timing closure. M05.12d.4 read-only risk/simulator discovery work is retained in main as a **M06 integration risk register/tooling**, not required to close M05. Do not mark vendor AXI functional XSim PASS; do not silently waive warnings. Board permission remains separate.

**Honest distinctions:** genuine HLS synthesis/resource/timing estimate and original HLS OOC implementation reports do NOT equal complete PS/PL routed timing; M05.11c standalone connected HLS+shell XSim does not imply the later file-backed PS/DMA .bd has been functionally simulated; no real board run, no physical DDR transfer, no energy/throughput measurement.
