It was *wrong* to accept a routed checkpoint or to waive timing.

**Working timing correction (D3.D.2C r2, retained in D3.D.2D):** compute one configured weighted recurrent edge per fabric cycle into an exact signed20 synapse accumulator; then pipeline the neuron update through registered `PHASE_BASE`, `PHASE_EXT`, `PHASE_TOTAL`, `PHASE_COMMIT`, preserving the existing M02/M03 numerical semantics (signed16, 3/4 decay with truncation toward zero, saturation, positive-delay recurrent spikes). The five active M06 edges + five processing stages cost **ten fabric clock cycles per neuron/tick**; this deliberately trades latency/throughput for closure. Keep full Icarus oracle parity before/after timing changes. D3.D.2C re-routed with **+2.675 ns WNS**, and the raw-event-added D3.D.2D image retained **+2.136 ns WNS**. These are routed slacks, **not measured hardware throughput/energy**.

## 2. Known-good owner PC and physical architecture

- **OS/tool:** owner Linux Ubuntu 24.04.5, **Vivado 2025.2**, K26 `xck26-sfvc784-2LV-c` (KV260). Source it using `source /home/dna/Vivado/2025.2/Vivado/settings64.sh`, then check `vivado -version`. Do not silently upgrade tools, chip part, IP versions, clock constraints, or hardware interface while reusing an accepted bitstream.
- **One independent new Vivado project for each candidate** — never edit/run within an accepted evidence project. The build Tcl creates a fresh project/block design and copies relevant RTL into an exclusive `~/Thesis_Evidence/M08/m08_<unique>_<random>` owner evidence directory, including the original source hash receipts. Use a **separate Git branch per architecture increment**.
- **PS–PL and clock:** Zynq UltraScale+ PS block supplies requested **PL0 nominal 100,000,000 Hz**. The PS clock **is still a dependency**; this does not establish clock independence from the PS. Source-derived **fabric power-on reset holds 256 clock cycles** after configuration, instead of using `pl_resetn0` as a JTAG data-path reset dependency. This distinction made JTAG-only PL tests feasible; it does not prove PS/Linux management compatibility.
- **JTAG PL path:** Vivado block design `jtag_axi:1.2` → `smartconnect:1.0` → (a) `axi_bram_ctrl:4.1` and `blk_mem_gen:8.4`, (b) standalone per-milestone **4 KiB neural AXI4-Lite peripheral**. Full 32-bit accesses. Fixed debug BRAM window `0xA0000000..0xA0000FFF`, neural peripheral window `0xA0001000..0xA0001FFF`. Before programming a new design, check actual BD mapping, JTAG interface and readback availability; do not infer valid address spaces from code alone.
- **PS HPM masters:** deliberately **DISABLED**, minimizing PS→PL AXI traffic and isolating the JTAG hardware demonstration from PS/DDR/Linux hazards. **No PS-MMIO/DDR implication** from a successful JTAG neural test. Do not enable an HPM/DDR interface as a casual convenience.
- **Cooling/fan routing:** PS `TTC0_WAVEOUT2` is routed via EMIO → top output `M08_FAN_PWM` constrained to **package pin A12**, `LVCMOS33` (SLEW SLOW, DRIVE 4). **This signal route alone cannot guarantee fan operation.** Owner **must verify independent powered active cooling** before any board programming, retain UART console capture and stock recovery, and avoid relying on the new PL configuration for cooling.
- **Vendor wrapper/source integrity:** generate and verify unique correct block-design HDL wrapper `m08_<phase>_lif_jtag_wrapper`, module-reference neural peripheral and PL clock/reset pin connectivity, actual BRAM controller-derived memory geometry/address window, and exactly two JTAG AXI address segments. Fail hard if missing/multiple/unexpected properties. No guessing replacement IP names, inferred reset or default addresses.
- **Known owner JTAG target/device:** `localhost:3121/xilinx_tcf/Xilinx/XFL1RK5M5ILQA`, `xck26_0`, debug master `hw_axi_1`. Check **fresh** target/device identity before every new owner-authorized programming attempt. Verify BRAM echo `55AA22DD` and milestone-specific magic/version (`M32N` v4 for D3.D.2C, `M32E` v5 for D3.D.2D) before neural comparisons. Do not connect/program a target if identity is ambiguous.

## 3. Four-stage gate that turned a good bitstream into accepted hardware evidence

### Stage A — source, oracle and real clocked RTL simulation, **no Vivado/board**

Build the next neural increment from a **source-controlled, numerically exact reference**. D3.D.2C/D3.D.2D reused original M06 G3.3 **32×4, five delayed recurrent edges, 17 signed external events**. Reference generation checks **M02 dense**, **M02 event/queued**, and **M03 sparse** agreement before producing the immutable test vector file. D3.D.2C uses 579 hex words (including **host-coalesced** per-neuron currents); D3.D.2D uses **630 words**, adding 17 individual `(neuron,tick,signed32 current)` triples. Its testbench passes if **128 fabric accumulated input buckets + 384 neural outputs** agree with reference, including BUSY/invalid/overflow/CLEAR/replay protocol negatives. The negative tests are not evidence of actual physical fault injection. Use `iverilog -g2012` and `vvp` against the **actual RTL module**; a skipped Icarus test does not count as success. Execute source-only policy gates and full `test_m08*.py` regression. Retain real CI on draft PR.

### Stage B — offline owner-PC Vivado 2025.2 bitgen, **no JTAG**

Use `scripts/run_m08_d3d2d_event_pc.sh` + `scripts/m08_d3d2d_event_build.tcl` as **historical examples**, not as a command to rerun an accepted D3.D.2D experiment. The shell insists on a new original `mktemp -d` evidence folder; the builder creates a fresh **exact K26** project and intact block design, checks the clock/reset, address geometry and fan pin, `launch_runs synth_1`, then `launch_runs impl_1 -to_step route_design -jobs 2`, loads the routed implementation, produces independent `report_drc`, `report_timing_summary`, `report_utilization`, `report_clocks`, and only then `write_bitstream`. Verify `Bitgen Completed Successfully`, not merely `Routing Is Done` or a log containing `impl_1`/checkpoint output. The builder refuses overwrites/impl mismatch and records Vivado version, original source hashes, separate neural/BRAM map, fan route and PS dependencies.

The owner native folder must preserve its **12 original evidence items** and `99_evidence_sha256.txt`: `00_vivado.log`, `01_vivado.jou`, `02_vivado_exit.txt`, `reports/10_fan_a12.xdc`, `reports/11_fabric_por.v`, `reports/12_synaptic_lif_axil.v`, `reports/20_route_drc.rpt`, `reports/21_route_timing.rpt`, `reports/22_route_utilization.rpt`, `reports/23_route_clocks.rpt`, `reports/30_native_result.txt`, and **the single new `bitstream_candidate/*_UNRELEASED.bit`**. Validate all twelve with `sha256sum -c 99_evidence_sha256.txt`. An original first-image gate exit **2** may mean **REVIEW REQUIRED**, *not* synthesis/route/bitgen failure. Never rerun the build just to force exit 0 or rewrite an evidence directory.

### Stage C — image-specific read-only native review, **still no board**

On the **original owner native folder**, inspect all 12 original hashes, original Vivado build exit 0, exact HDL RTL/POR/builder source digest, correct IP/address/clock metadata, distinct bit SHA+bytes, route constraints, setup/hold/pulse-width endpoint status, unconstrained clock paths, and **all DRC warnings individually**. D3.D.2C/D3.D.2D each generated exactly **7 vendor debug/JTAG advisories**, but with DIFFERENT XSDB physical LUT pins and equations. They are **not transferable allowlists**. Specifically, D3.D.2D used `PDCN-1569` LUT **A2/I1, A3/I0, A5/I0**, `REQP-1857` vendor JTAG RX BRAM18, two `REQP-1858` vendor JTAG RD/WR command BRAM36 WRITE_FIRST collision advisories, and `RTSTAT-10` 39 unroutable nets/37 listed/only first 15 printed. The original full D3.D.2D DRC report SHA **`f1cc7a7b72b7eeee85828a6c5f7cb75d56894a55a2143cfe4e0f1f6c8098ebee`** pins its bytes; only the first 15 RTSTAT entries are individually seen. Warnings confined to vendor debug hardware are *reviewable*, **not proof collisions are impossible**. Do **not** waive arbitrary DRC or downgrade setup violations to warnings. If implementation failed timing, first extract actual worst startpoint/endpoint, path levels, route vs logic delay, then fix RTL microarchitecture and create a **new** candidate.

After explicit original-owner first-image review, implement a **new image-specific** validator with deterministic mutation-negative tests (wrong bit bytes even with rehashed ledger, wrong source RTL/builder, LUT pin/equation, FIFO path, RTSTAT sample, additional warning, failure in timing) and require **owner-local exit 0**. GitHub CI never sees the owner's private `~/Thesis_Evidence` files. Native PASS is **never physical PASS**.

### Stage D — independently cooled, manually owner-armed single JTAG program and physical readback

Prior to a **new** physical experiment: verify stock recovery/boot, stable power, **separately verified active cooling**, UART capture enabled, K26 physical hardware target identity, exclusive JTAG (no competing Hardware Manager client), exact tool version and accepted image, and explicit consent. Only after native gate PASS enable *two distinct, experiment-specific* arming variables e.g. `M08_<phase>_ALLOW_PROGRAM=YES` **and** `M08_<phase>_PREFLIGHT_CONFIRMED=YES`. Do not keep these set in startup shells. A dedicated one-shot physical shell re-runs the immutable native gate **before** any JTAG call, checks exact image SHA/size/folder, creates a new `HW_XXXXXXXX` evidence folder, saves the *exact executed Tcl*, and starts one Vivado hardware session. The Tcl has **one** `program_hw_devices` instruction, validates unique exact K26 and `hw_axi_1`, probes BRAM, checks distinct magic/version and compares the full reference trace, then closes JTAG cleanly. It must **never** auto-retry programming on a failure. Do not reflash QSPI, rewrite SD, touch PS MMIO/DDR or run Linux management commands as a side effect.

The physical runner preserves a **six-file** SHA256 receipt: `00_executed_source.tcl`, `01_jtag_m06.log`, `02_jtag_m06.jou`, `03_exit.txt`, `10_m06_*_golden.hex`, `80_m06_*_hw_parity.txt`. Independently audit original native gate, these six byte receipts, exact executed Tcl, one actual JTAG program event, target/AXI/BRAM/neural identity, complete M02/M03 numerical readbacks and expected physical-counter markers. A mock auditor unit test is **only parser validation**. Only the owner's genuine first physical folder and independent auditor PASS close the bounded milestone.

## 5. Next experiment design guidance

The next valuable physical boundary after D3.D.2D is not another repetition of the same full 32×4 trace. It is **decoupling event arrival from neuron update**: a bounded **on-FPGA event FIFO/queue with explicit tick-aware consumption**, deterministic overflow/backpressure and a separately verifiable event-service readback. Start by keeping the **32-neuron/4-tick/five-recurrent-edge/17-event original M06 fixture** and existing `M32E` numerical behavior, but add a **distinct new version/magic and a separate real clocked RTL testbench** that proves queue ordering, delayed consumption, signed coalescing, and rollback/clear/reset behavior. Only after that is physically validated should later work attempt autonomous event scheduling, AXI streaming, DMA, sparse neuron skipping, DDR memory virtualization, performance or true PS-clock independence. **This is a proposed D3.D.2E scope**, subject to current roadmap review—not a pre-existing physical success or an unapproved commitment to DDR/HLS. Preserve source-level deterministic equivalence, negative tests, new original evidence and the four-stage gate above.
