# M11 HLS Computational Core

This directory starts the hardware implementation of the frozen M10 FPGA-v1 computational-core specification.

## Standard M11 toolchain

M11 and later FPGA-development work standardize on:

```text
AMD Vitis  2025.2
AMD Vivado 2025.2
```

The command-line HLS flow uses the 2025.2 Unified IDE tools:

- `vitis-run --mode hls --csim` for C simulation;
- `v++ -c --mode hls` for HLS synthesis;
- `vitis-run --mode hls --cosim` for C/RTL co-simulation;
- `vitis-run --mode hls --package` for the later Vivado-IP packaging step.

The repository no longer uses the legacy `vitis_hls -f ...` project script as the primary M11 flow.

## Scope of the current HLS top

M11.1 established the smallest useful synthesis boundary: one complete neuron state transition. The HLS top function is:

```text
neuron_step_v1(...)
```

It consumes current, voltage, refractory state, already-accumulated integer synaptic input, current/voltage decay, threshold, bias, reset voltage, and configured refractory duration. It produces next current, next voltage, next refractory state, and spike/no-spike.

Synapse-memory traversal, per-neuron accumulation, recurrent event routing, tick scheduling, host interfaces, and trace buffering remain outside this top function. Those pieces are integrated in later M11 sub-milestones after neuron arithmetic has an independently verified HLS implementation.

## Frozen M10 semantics implemented

The C++ datapath follows the FPGA-v1 contract rather than relying on native C/C++ overflow behavior:

```text
I_work = SAT24(I0 + S)
I_next = SAT24(DECAYED(I_work, current_decay))
```

For a non-refractory neuron:

```text
V_decay_base = DECAYED(V0, voltage_decay)
V_work       = SAT24(V_decay_base + I_work + bias)
spike        = (V_work > threshold)
```

A spike hard-resets voltage and loads `max(refractory_ticks - 1, 0)`. A blocked refractory tick still updates current, holds voltage at reset voltage, suppresses spiking, and decrements the refractory counter.

Decay removes:

```text
round_away_from_zero(value * decay / 4096)
```

Because `4096 == 2^12`, the HLS implementation computes the magnitude ceiling with an add-and-shift operation while preserving the exact M10 integer result.

## HLS widths

The frozen architectural state uses:

- `ap_int<24>` current and voltage;
- `ap_uint<16>` refractory state;
- `ap_uint<13>` decay configuration;
- `ap_uint<1>` spike output.

The current HLS boundary uses a signed 64-bit integer for the already-accumulated synaptic-input scalar and intermediate arithmetic. M11.2 deliberately limits randomized synaptic-input vectors to signed 32-bit values: that range is large enough to stress both SAT24 boundaries while avoiding a false claim that the final physical accumulator/event capacity has already been frozen. That capacity remains M11.5 work.

## M11.1 C-simulation gate — complete

The original self-checking C++ testbench contains 11 hand-written directed cases. The independently reproduced M11.1 vendor run under Vitis 2025.2 finished with:

```text
M11.1 HLS neuron-step tests passed: 11 cases
```

This established that the HLS C++ source compiles under the selected vendor toolchain and reproduces the directed M10 equations.

## M11.2 Python-to-HLS differential gate — complete

M11.2 extends C simulation so expected values come directly from the frozen Python FPGA-v1 profile instead of being hand-copied into C++.

The Python source of truth is:

```text
NeuronState + NeuronConfig
          ↓
step_neuron(..., arithmetic=FPGA_CORE_ARITHMETIC_V1)
          ↓
expected current / voltage / refractory / spike
```

`src/neuromorphic_twin/hls_conformance.py` generates the comparison corpus and `examples/generate_m11_hls_vectors.py` provides its CLI. The standard corpus is deterministic:

```text
directed boundary cases: 24
seeded random cases:   2048
---------------------------
total:                 2072
seed:             0x4D313132
```

The pseudo-random stream is generated by an explicitly implemented SplitMix64 sequence rather than Python's library RNG, so the corpus is tied to the stored algorithm and seed rather than a Python-version-specific random implementation.

The directed set covers strict threshold equality/just-over behavior, positive and negative SAT24 boundaries, decay endpoints and representative interior values (`0`, `1`, `2048`, `4095`, `4096`), positive and negative round-away-from-zero behavior, refractory state/configuration boundaries through `65535`, bias saturation, reset boundaries, and large accumulated synaptic inputs. The seeded corpus then sweeps the legal FPGA-v1 state/configuration ranges while intentionally keeping many neurons non-refractory so threshold/spike behavior is exercised heavily.

The generator writes an ephemeral C++ initializer named `generated_m11_2_vectors.inc` inside the no-space HLS staging directory. It is not committed; the repository stores the generator, fixed seed, and tests that reproduce it.

Dedicated Python tests verify deterministic generation, required boundary presence, exact golden-model replay, and byte-for-byte reproducible initializer output. The independently reproduced completion run passed both the Python tests/regression suite and the Vitis 2025.2 differential C simulation, which finished with:

```text
M11.2 Python/HLS differential tests passed: 2072 cases (directed=24, random=2048, seed=0x4d313132)
```

Every vector compares current, voltage, refractory state, and spike exactly. Any mismatch prints the vector name plus expected and actual outputs and returns a nonzero status.

## Running the combined M11.1 + M11.2 C simulation

First source the Vitis/Vivado 2025.2 environment and export the frozen target part:

```bash
export HLS_PART='xck26-sfvc784-2LV-c'
```

Then, from this directory:

```bash
bash run_csim.sh
```

Because the repository path contains `Neuromorphic Digital Twin`, the wrapper stages the HLS component under `/tmp/neuromorphic_twin_hls_<uid>/...` before invoking Vitis; Vitis HLS 2025.2 rejects project/solution paths containing spaces.

## M11.3 synthesis + C/RTL co-simulation — in progress

M11.3 converts the behaviorally verified C++ into actual RTL and verifies that RTL against the same Python-golden corpus.

### Frozen baseline

For the first synthesis baseline M11.3 fixes:

```text
target part:        xck26-sfvc784-2LV-c
HLS clock period:   10 ns (100 MHz)
clock uncertainty:  12%
flow target:        Vivado
RTL output format:  rtl
```

The 100 MHz target is an initial measurement/verification point, not a claim about the final maximum frequency. Later optimization may change the clock only after the first report is recorded and any change is evaluated explicitly.

These settings live in `hls_config.cfg` as `clock=10ns`, `clock_uncertainty=12%`, `flow_target=vivado`, and `syn.output.format=rtl`.

### Reproducible M11.3 command

`run_m11_3.sh` performs the complete M11.3 vendor flow from a clean no-space staging directory:

1. verifies Python, Vitis, `vitis-run`, `v++`, and Vivado are available and report 2025.2;
2. requires `HLS_PART` to equal the frozen `xck26-sfvc784-2LV-c` target;
3. regenerates the exact 2,072-vector M11.2 Python-golden corpus;
4. runs HLS C synthesis with `v++ -c --mode hls`;
5. locates and copies the `*_csynth.rpt` report into ignored `build/m11_3/` output;
6. prints selected clock, latency, initiation-interval, and BRAM/DSP/FF/LUT report lines;
7. runs `vitis-run --mode hls --cosim` using the same synthesized component and the same golden vectors;
8. saves synthesis/co-simulation logs under ignored `build/m11_3/`.

Run it with:

```bash
export HLS_PART='xck26-sfvc784-2LV-c'
bash run_m11_3.sh | tee m11_3_2025_2.log
```

A successful command proves that Vitis accepted the design for synthesis and that generated RTL passed the C/RTL testbench. M11.3 is not complete until the actual synthesis report is reviewed for latency, II, timing estimate, resources/operator mapping, relevant warnings are resolved or documented, and the co-simulation result is recorded.

## What comes after M11.3

M11.4 packages the verified RTL as Vivado IP and creates the real Vivado system project/block design. M11.5 then integrates memories, synaptic traversal/accumulation, tick control, recurrent routing, and observability; M11.6 produces and programs the first integrated bitstream.
