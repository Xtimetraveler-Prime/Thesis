# Computational Core Specification v1

This document is the implementation-neutral behavioral contract for the first
FPGA computational core. It freezes the subset of the Python golden model that
has already been validated through M09 and gives later RTL/HLS work one
normative definition of an algorithmic tick, architectural state, arithmetic,
neuron behavior, synaptic accumulation, and recurrent routing.

The words **MUST**, **MUST NOT**, **SHALL**, and **SHALL NOT** are normative.
Requirement identifiers are stable labels used by the M10 conformance matrix.

## Scope and profile boundary

This specification describes a Loihi-inspired project profile, not a claim that
every undocumented Intel Loihi microarchitectural detail is reproduced.
Published Loihi descriptions allocate 24-bit precision to current and membrane
state and use a 12-bit fractional decay scale. This project therefore freezes
24-bit signed current and voltage state while preserving the already validated
`0..4096` decay-factor domain used by the Python/Brian2Loihi comparison path.

M08 separately freezes the static-weight source representation and FPGA weight
memory image. M09 freezes deterministic recurrent spike routing. M10 combines
those behaviors into the computational-core contract that M11 must implement.

# M10.1 — Execution and architectural-state contract

## 1. Algorithmic time

**CORE-TICK-001 — Discrete tick index.** The core SHALL evolve only at integer
algorithmic ticks `t = 0, 1, 2, ...`. Hardware clock cycles used to implement a
tick are not architecturally visible.

**CORE-TICK-002 — Atomic tick observation.** A trace for tick `t` SHALL describe
one complete state transition from the state committed after tick `t-1` to the
state committed after tick `t`. Partially updated neuron state SHALL NOT be
visible as input to another neuron during the same tick.

## 2. Normative per-tick schedule

Every tick SHALL be behaviorally equivalent to the following ordered phases.
An implementation may pipeline, parallelize, or time-multiplex these phases as
long as externally visible results are identical.

### Phase A — latch input events

Let `E[t]` be the externally supplied axon-event sequence for tick `t` and let
`R[t]` be the recurrent axon-event sequence queued by spikes from tick `t-1`.

```text
input_axons[t] = E[t] || R[t]
```

where `||` means sequence concatenation.

**CORE-TICK-003 — Input ordering.** External axon events SHALL precede recurrent
axon events in the consumed event sequence. Multiplicity SHALL be preserved;
events SHALL NOT be deduplicated.

### Phase B — accumulate synaptic input

For every event in `input_axons[t]`, all synapses in that axon's fan-out row are
visited. Each synapse contributes its effective integer weight to its target
neuron's tick-local synaptic sum.

```text
synaptic_input[n] = sum(weight for every delivered event/synapse targeting n)
```

**CORE-TICK-004 — Tick-local accumulation.** Synaptic accumulation SHALL use
state committed before the neuron-update phase. The accumulation temporary is
not architectural state and may be wider than the current register, but it MUST
preserve the exact mathematical sum until the state arithmetic rule is applied.

### Phase C — update every neuron

Each neuron consumes exactly three categories of information:

```text
previous architectural state
per-neuron configuration
synaptic_input[n] for this tick
```

All neuron transitions are conceptually independent and SHALL be computed from
the same pre-tick state snapshot.

### Phase D — collect spikes

Spikes generated by Phase C are collected in ascending neuron-ID order.

**CORE-TICK-005 — Stable spike order.** If multiple neurons spike on one tick,
the architectural output spike sequence SHALL be ordered by ascending source
neuron ID.

### Phase E — generate recurrent events

For each spike, the source neuron's declared spike routes are emitted in route
declaration order. The resulting sequence becomes the pending recurrent event
sequence for the next tick.

### Phase F — commit

The core atomically commits all next-neuron state, the pending recurrent event
sequence, and the incremented tick index.

**CORE-TICK-006 — Next-tick recurrence.** A spike emitted on tick `t` SHALL NOT
produce synaptic input on tick `t`. Its routed axon events can first be consumed
on tick `t + 1`.

## 3. Architectural state and widths

Only values in this section are architectural state that must survive between
algorithmic ticks. Internal products, sums, loop counters, pipeline registers,
and staging FIFOs are implementation details unless they are required to
preserve these values exactly.

### 3.1 Per-neuron dynamic state

| State | Signedness | Width | Reset value | Meaning |
|---|---:|---:|---:|---|
| `current[n]` | signed two's complement | 24 bits | `0` | decaying synaptic-current state |
| `voltage[n]` | signed two's complement | 24 bits | `reset_voltage[n]` | membrane-voltage state |
| `refractory_remaining[n]` | unsigned | 16 bits | `0` | number of future blocked ticks still to execute |

**CORE-STATE-001 — Current width.** Stored current SHALL be a signed 24-bit
two's-complement value.

**CORE-STATE-002 — Voltage width.** Stored voltage SHALL be a signed 24-bit
two's-complement value.

**CORE-STATE-003 — Refractory width.** Stored refractory state SHALL be an
unsigned 16-bit integer.

### 3.2 Core-global dynamic state

| State | Signedness | Width | Reset value | Meaning |
|---|---:|---:|---:|---|
| `tick` | unsigned | 32 bits | `0` | current algorithmic tick index |
| `pending_recurrent_axons[]` entries | unsigned | 16 bits each | empty sequence | ordered events to consume at the next tick |

**CORE-STATE-004 — Tick width.** Hardware SHALL expose at least the low 32 bits
of the algorithmic tick index. The v1 conformance window assumes no 32-bit tick
wrap occurs during a test run.

**CORE-STATE-005 — Axon ID width.** External and recurrent axon identifiers SHALL
be unsigned 16-bit values, matching the M08 CSR axon-address contract.

### 3.3 Per-neuron configuration registers

| Configuration | Signedness | Width | Valid domain |
|---|---:|---:|---|
| `current_decay` | unsigned | 13 bits | `0..4096` |
| `voltage_decay` | unsigned | 13 bits | `0..4096` |
| `threshold` | signed two's complement | 24 bits | stored effective threshold |
| `bias` | signed two's complement | 24 bits | additive voltage drive |
| `reset_voltage` | signed two's complement | 24 bits | must be less than `threshold` |
| `refractory_ticks` | unsigned | 16 bits | `0..65535` |

The decay fields require 13 physical bits in this project profile because the
validated software contract includes the endpoint `4096 = 2^12`, which denotes
full decay in one algorithmic tick.

**CORE-STATE-006 — Decay representation.** Current and voltage decay SHALL use an
integer factor in `0..4096` with denominator `4096`.

**CORE-STATE-007 — Neuron configuration width.** Threshold, bias, and reset
voltage SHALL use signed 24-bit effective-value registers; configured refractory
duration SHALL use 16 unsigned bits.

### 3.4 Routing identifiers

`source_neuron` and `target_axon` in a recurrent route SHALL each use unsigned
16-bit identifiers. Synapse target-neuron identifiers and M08 frozen-storage
axon identifiers use the same 16-bit ID space.

**CORE-STATE-008 — Route ID width.** Recurrent route source-neuron and target-axon
identifiers SHALL be unsigned 16-bit values.

## 4. Reset state

A core reset SHALL perform the following architectural transition before the
next tick is accepted:

```text
tick                      = 0
current[n]                = 0 for every neuron
voltage[n]                = reset_voltage[n] for every neuron
refractory_remaining[n]   = 0 for every neuron
pending_recurrent_axons   = empty
```

**CORE-STATE-009 — Reset determinism.** Reset SHALL discard all pending recurrent
events and restore a deterministic power-on state. Replaying the same external
input sequence after reset SHALL produce the same trace.

## 5. M10.1 completion boundary

M10.1 freezes:

- the six-phase algorithmic tick schedule;
- pre-state/next-state isolation across a tick;
- stable input and spike ordering;
- next-tick-only recurrent delivery;
- architectural state and configuration widths;
- deterministic reset state.

Arithmetic, rounding, overflow, threshold/reset/refractory equations, detailed
routing semantics, and requirement-linked tests are frozen by M10.2 and M10.3.
